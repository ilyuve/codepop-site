03 REAL PAIN / 真实场景痛点

代码不死，但没人记得它在哪。

// 当 AI 也读不懂你的私有代码库，grep 不到、token 烧光、调用链断裂 就成了日常。

R.I.P. CONTEXT

硬塞 AI 读全部代码，
优雅 又 烧钱。

通用 LLM 不认识你的私有代码库——它没读过你的 utils/，也不知道你三年前在 legacy/ 里写过的状态机。

于是大家被迫做三件蠢事：
① 把整个 repo 灌进 context window，token 哗哗地烧；
② 用 grep 大海捞针，搜得到字符串、搜不到语义；
③ 改一个上游字段，赌下游不会崩。

Code:Pop 让你的代码库，先变成一座本地、可被语义检索的"活字典"。

SCENARIO 01 / TOKEN 黑洞
"AI 硬读代码库，Token 烧了 ¥5万，还没找到关键关联。"
◆ 30 万行 monorepo · 全量塞 context
◆ 5 轮迭代后 仍漏掉跨服务调用
SCENARIO 02 / GREP 失忆
"grep 搜不到语义，只记得功能，不记得函数名。"
◆ 想找"超时重试" · 但写的是 backoffWrapper
◆ 翻 12 个 commit 也想不起来
SCENARIO 03 / 调用链断裂
"改了上游字段，下游 三个服务崩了，没人记得调用链。"
◆ user.id → int 改 string
◆ 3 个微服务连锁报错 · 凌晨 3 点回滚
04 CORE FEATURES × 3 / 三大核心功能

让代码库，持续生长。

// 三个能力共同构成 Code:Pop 的"代码神经系统"——索引、检索、自愈。

01
FEATURE / 实时

实时索引

REAL-TIME INDEXING

基于 tree-sitter AST 解析，函数级切片精准提取代码语义单元，毫秒级写入 PostgreSQL + pgvector。Git 提交自动触发索引更新，工作流零打扰。

▸ STACK: FastAPI · tree-sitter · BAAI/bge-m3 · PostgreSQL + pgvector
$ git clone https://github.com/ilyuve/code-pop.git
$ cd code-pop && docker compose up -d

✓ initial scan: 1,247 files / 41,892 chunks
✓ embedding model: BAAI/bge-m3
✓ vector store: PostgreSQL + pgvector

# Git push 自动触发
[12:04:31] PUSH  src/auth/jwt.go
       └─ parse_ast() → 3 chunks
       └─ embed() → 1024-dim
       └─ ✓ store() in 23ms
02
FEATURE / 语义

语义检索

SEMANTIC SEARCH

BAAI/bge-m3 嵌入模型 把代码与查询编码到同一向量空间，理解代码语义而非关键词匹配。忘了函数名也能找回来。

▸ STACK: bge-m3 (1024d) · cosine · top-k=5 · re-rank
codepop> ask "用户登录的 JWT 验证"

# vectorize query → cosine search
→ found 3 matches in 87ms:

  ★ 0.94  src/auth/jwt_verify.go:42
        // validate token signature ...
  ★ 0.91  api/middleware/auth.go:18
        // extract Bearer token ...
  ★ 0.87  legacy/login/handler.py:7
        // decode_jwt(token) ...
03
FEATURE / 增量

增量更新

INCREMENTAL UPDATE

GitHub Webhook + 本地 git 监听 双引擎，只重新索引变更的代码块，不全量扫描。每一次 push 都让记忆悄悄长大。

▸ STACK: GitHub Webhook · git diff · delta-chunking · pgvector
$ git push origin main
# GitHub Webhook → codepop sync

▸ diff vs HEAD~1:

   ~  src/auth/jwt.go        [~3 chunks]
   -  legacy/auth_old.py     [-1 chunk]

✓ delta indexed in 142ms
✓ total alive: 41,903 chunks

A
SCENARIO 01 / SOLO DEVELOPER

独立开发者 · 找回旧物

"我两年前肯定写过一个限流算法，就是想不起来在哪了。"
  1. 打开 Code:Pop 索引全部本地 repo
  2. 问："令牌桶限流的实现"
  3. 跨 12 个项目语义匹配 (cosine ≥ 0.85)
  4. 0.3 秒返回 4 段相关代码 + 调用上下文
  5. 复制 → 改 2 行参数 → 直接用上
